Audit baseline: `95a2f73`, September 2026. This document supersedes historical
completion claims for the areas listed below. The issues describe work still
needed, not features already delivered.

## First repair

The Pokémon record codec used signed floor-modulo for an unsigned personality.
The correction uses unsigned remainder for shuffle and nature. Independent
wire records cover every shuffle on both sides of the sign boundary. A local
read-only check established that the reported missing party is readable with
the corrected decoder; no user data or identifying values are included here.
Do not rewrite a genuine save as a migration for this correction.

## Visual direction

Yoru has two central jobs: start a study session and continue a saved game.
Make those actions obvious, and make their persistence status trustworthy.
The crescent and restrained palettes provide character; typography and clear
hierarchy provide everyday usability. Decorative scenes must never obscure
missing data or compete with the clock.

The HTML companion is a design reference, not a running replacement app. Its
controls switch reference screens only; all data are invented. The native
Swing implementation remains the product. Measurements in issues #8/#9 are
logical pixels, not screenshot device pixels.

## Component contract

- Body/navigation: system sans, 14px; captions 12px; section titles 16px;
  page title 28px semibold. Monospace is reserved for timer and numeric values.
- Spacing: 4, 8, 12, 16, 24, 32. Content padding 24. Card border 1px,
  radius 12; control radius 8, minimum height 36.
- Each region has one accent action. Destructive actions use a secondary
  placement with explicit confirmation and the existing backup policy.
- Text wraps. A tooltip is never the only source of a required instruction.
- Focus is visible, 2px, and selection uses more than color. Standard Swing
  accessible components are preferable to a single canvas full of hit boxes.
- Preserve all four palettes. Validate foreground/background pairs in each
  real state, including hover, selected, disabled, focus and errors.

## Screen specifications

### Today

Order: title; timer/activity with one clock action; partner; today's agenda;
statistics/history. Above 1040 content width, timer and partner may sit beside
one another at 60/40; below it stack. Do not repeat Clock in/out in the partner.
The partner shows name, level and last durable save status. An unknown record
is not described as an unchosen starter. No companion promotions here (#3).
The chosen optional portrait remains supported as specified by that issue.

### Collection

Party comes before reward queues. Six cards at wide width, 3×2 at narrow width.
Each card has image, name, level; image failure leaves text intact. PC uses a
6×5 grid, previous/next and a box selector with occupancy. At narrow widths,
selected details go beneath the grid. Keep arrangement explicit and cancellable.
Preserve selection and scroll after successful save updates. Read-only running
state permits inspecting records but blocks mutation at action time as well
as disabling controls. Keyboard instructions and accessible names are required.

### Game

Saved campaign and setup are separate sections, always visible. Missing core
only disables Play. Existing save export is always available. Before Play,
show readiness for game file, core and save compatibility. Artwork is optional.
While running show play/pause/close, controls help and durable-save status.
When persistence fails, show Retry and preserve the session owner until safe.
No automatically discarded save, no silent game with saving disabled.

### Tasks

Add task is primary. Group import options in one secondary menu. Filters and
sort have different visual roles. Rows show title, state, due date and activity;
rare actions belong in the trailing menu. Do not make every row look like a
control panel. Preserve drag/reorder, keyboard alternatives and task tracking.

### Habits, Schedule and Data

Consume the same typography, controls and spacing; do not redesign semantics.
Habits use a clearly labeled check action and editable target, with empty and
completed states. Schedule preserves drag creation/resizing plus keyboard
and dialog alternatives; provide a clear current-day indicator and readable
plan/actual legend. Data prioritizes period/filter, headline totals, then
charts with textual summaries. Dense charts can scroll; normal prose cannot
be clipped. Preview fixtures must cover long labels and empty history.

### Settings and vault dialogs

Sections: Appearance, Tracking, Game & artwork, Vault. Keep appearance choices
compact; persist selection without jumping to the page top. Companion picker
and recommendations only here. Artwork is split into categories with status
and repair actions. Password-free vault creation remains explicit; error
messages stay inside the dialog and preserve entered non-secret values.

## State matrix for the implementation agents

| Condition | Display | Allowed actions |
|---|---|---|
| No save | Save once inside the game | Setup, Play when ready |
| Readable save, no core | Party and saved status | Inspect, export, configure core |
| Unreadable save | Save present; cannot read | Export original, setup; no record edits |
| Missing artwork | Name/level and neutral placeholder | Inspect, repair artwork |
| Game running | Last durable snapshot | Inspect; no storage edits |
| Save pending | Saving to your vault | Continue; Close waits safely |
| Save write failed | Could not save; Retry | Retry; no unsafe vault disposal |
| Partial artwork import | Ready and missing categories listed | Use good categories, retry missing |
| No rewards | Compact progress to next encounter | No oversized empty reward panels |

## Original artwork delivery

`../media/yoru-moonlit-landscape.png` is an original generated landscape,
2172×724, made with the built-in image-generation tool. It contains no game
art. Use it only as optional decorative study scenery. Draw at aspect ratio
3:1, height 160–180, cover crop centered; prefer preserving the right-side
moon. Do not stretch. Do not put body text over the image. Static in reduced
motion mode, and no animation is required. It is supplied as design/release
media here; the UI integration issue must decide its runtime resource path
under the repository's original-art policy without weakening PrivacyTest.

Prompt: “Original decorative background for Yoru, a quiet desktop study
workspace. Wide 3:1 panoramic illustration, sophisticated restrained
hand-painted anime environmental art. Moonlit indigo hills and a small
reflective lake with muted teal reeds, distant atmospheric mountains and one
delicate crescent moon on the right. Center-left mostly calm dark negative
space; low visual complexity and gentle tonal contrast. Deep blue-black,
slate, dusty teal and restrained pale moonlight. No people, creatures,
Pokémon, buildings, game assets, text, interface, logos or watermark. Refined
and restful, not neon; no pixel-art imitation.”

Existing logo stays vector/code-native. Pokémon sprites and PC backgrounds
must be decoded from local user-supplied assets, never replaced with generated
lookalikes. No extra bitmap icons are needed: use native controls and the
existing icon vocabulary. Companion portrait expansion remains scoped to #3;
this audit does not claim to deliver a new portrait catalog.

## Evidence and release gates

Baseline tests failed on installed-art dependence in StorageTest. Tests now
use an isolated home and an in-memory Preferences factory, including macOS.
The new codec oracle fails before and passes after the unsigned fix.

Audit renders covered every page at desktop and minimum dimensions in all
four themes; detailed visual review sampled Today, Collection, Tasks, Game
and Settings, plus the installed app's save/party flow. Remaining native
keyboard, dialogs, full campaign and platform installer verification are
release work, not implied by a green headless suite.

Each implementing PR must record: precise defect, changed behavior, tests,
rendered states reviewed, limitations, and dependency issue. A small green
PR is preferred to a cross-cutting rewrite with unverified screenshots.
